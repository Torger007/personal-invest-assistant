# 持仓复盘一期结果契约（第一步锁定）

实现依据：`docs/portfolio-review-agent-phase1-plan.md`。机器可校验结构位于 `backend/app/agent/contracts.py` 的 `PortfolioReviewResult`；固定日期样例位于 `backend/evals/portfolio_review_contract_cases.jsonl`。本文件约束后续 Skill、持久化与页面，不代表 Agent 流程已接入。

## 报告与关注项

- `status` 为 `ready` 或 `degraded`；运行中的任务状态由持久化任务记录单独表示。降级报告必须列出 `limitations`。
- `as_of.run_at` 是复盘运行时间；`holdings` 按持仓 ID、`fund_nav` 和 `advice` 按基金代码保留实际数据日期，市场数据单独标注。报告日期不等于净值日期。
- `findings` 最多三项。每项有标题、类型、重要性、当前证据 ID、与上次的关系、下一步观察条件。实质性关注项至少有一条有效证据，证据 ID 必须存在于报告证据集合中。
- 候选项按持仓影响、变化幅度、风险紧迫性、已确认偏好和证据质量筛选。有效项不足三项时，页面空位显示“暂无更多有证据支持的新变化”，不生成虚构关注项。
- 报告解释可以描述集中度、变化和观察条件。具体操作、目标仓位及置信度只能引用有效 `DecisionArtifact`；质量门降级时不得新增目标仓位。

## 比较语义

- `first_review` 无 `previous_review_id` 和变化项；页面显示“暂无上次判断可比较”。
- `compared` 必须指向同一用户最近一次成功、数据契约完整的持仓复盘。普通聊天摘要、单基金建议和失败运行不能充当基线。
- `changes_since_previous.kind` 区分 `holding`、`data`、`rule`、`continuity`。每项保存本次和上次的证据 ID 及时间。同日重复运行显示各自运行时间；数据不变时只能描述判断延续，不能以模型措辞变化冒充市场变化。

## 失败案例与后续评测

| 场景 | 预期 |
| --- | --- |
| 空持仓或单基金 | 不凑齐三项；只报告可证实事实或数据限制 |
| 无净值、过期净值、节假日 | 按实际交易日和公布时间判断；必要时降级，绝不称旧净值为今日净值 |
| 建议缺失、工具失败、来源未知、数据冲突 | 标注缺口与来源；不编造建议、来源或收益 |
| 持仓增删、份额变化、偏好或规则版本变化 | 逐项引用两次证据和时间，区分变化类型 |
| 同日重复且数据未变 | 标注两次运行时间和判断延续 |
| 跨用户访问 | 拒绝读取他人的持仓、偏好、复盘和证据 |

当前样例先覆盖结构契约的首次、同日延续、降级和无证据拒绝。完整离线运行评测、真实模型问题集与前端端到端检查在第六步实施。

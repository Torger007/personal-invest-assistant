# 股票分析技术助手演进方案

## 1. 目标与边界

### 1.1 产品目标

在现有“基金组合分析 + AI 问答”系统上，新增一个面向单一标的的股票分析技术助手。用户可在浏览器中输入代码、选择市场，系统获取可靠行情数据，计算统一的技术指标与 0–100 综合评分，并生成可解释、带风险提示的分析报告。

首个可发布版本（MVP）优先服务 A 股个股和场内 ETF；港股、美股、LOF 采用同一套领域模型和接口，随后分阶段接入。已有基金组合、板块、建议、AI Agent、账户和部署能力继续保留。

### 1.2 非目标

- 不提供自动下单、交易通道或收益承诺。
- 不将 LLM 作为指标计算和评分的唯一依据；数值分析必须可复现。
- 不在第一期承诺实时逐笔行情。首期以日线和明确标注延迟的最新行情为主。

### 1.3 成功标准

用户完成“输入代码 → 选择市场 → 运行”的路径后，应在可接受等待时间内获得：

1. 标的身份、行情时间和数据状态；
2. K 线、成交量和技术指标图层；
3. MA5/20/30/60、MACD、RSI、布林带、ATR 等明确数值；
4. 0–100 综合评分、趋势标签、操作倾向与风险等级；
5. 每项结论对应的数据证据、指标阈值和风险提示；
6. 可回看、可比较、可追溯的历史报告。

## 2. 当前基础与演进判断

| 现有能力 | 可复用部分 | 本方案中的作用 |
| --- | --- | --- |
| FastAPI + PostgreSQL + Alembic | API、异步 ORM、迁移、容器启动流程 | 新增行情、标的、报告等表和 API |
| Vue 3 + Element Plus + ECharts | 路由、图表、主题、登录态 | 新增标的搜索与分析报告页 |
| AKShare 采集 | A 股指数、基金、板块采集经验 | A 股/ETF 的首个行情适配器 |
| 分析器与 Advisor | `AnalysisResult`、综合评分、风险文本 | 拆成适配股票的指标计算和评分引擎 |
| AI Agent | 工具注册、计划、SSE、历史会话 | 将结构化报告解释为自然语言，不承担算数 |
| 鉴权与用户隔离 | Cookie、CSRF、用户级建议记录 | 自选标的、报告历史、配置隔离 |

核心调整是把“基金净值序列分析”与“真实 OHLCV 行情分析”分离。股票/ETF 必须以真实开高低收成交量为输入；基金净值仍走现有基金分析流程，避免伪造 K 线和无效量价判断。

## 3. 用户体验设计

### 3.1 主流程

```mermaid
flowchart LR
  A[输入代码或名称] --> B[选择/自动识别市场]
  B --> C[校验标的身份]
  C --> D[获取行情与数据质量检查]
  D --> E[计算指标与评分]
  E --> F[结构化分析报告]
  F --> G[AI 解释、收藏、查看历史]
```

### 3.2 页面与功能

| 页面 | 用户动作 | 交付内容 |
| --- | --- | --- |
| 标的分析首页 | 搜索代码/名称，选择 A 股、HK、US、ETF、LOF，点击运行 | 最近搜索、自选列表、市场状态 |
| 分析报告页 | 切换周期、查看指标、请求 AI 解读 | 行情摘要、评分、K 线/成交量、指标、证据、风险、历史报告 |
| 自选与对比页 | 收藏、删除、选择 2–5 个标的 | 评分、趋势、波动、成交量、报告日期横向比较 |
| 数据状态页（管理员） | 查看源状态和刷新任务 | 主/备源、最后成功时间、失败率、延迟、告警 |

### 3.3 报告信息架构

报告顶部首先显示“数据截至时间、市场状态、综合分、趋势、风险等级”。其后依次展示：

1. 趋势：价格与 MA5/20/30/60 的关系、均线排列、突破/跌破；
2. 动量：MACD 线、信号线、柱体、RSI 与超买超卖状态；
3. 波动：布林带位置、带宽、ATR 及 ATR 百分比；
4. 量价：当日/近 5 日相对成交量、价量同步或背离；
5. 评分与操作倾向：买入观察、持有、减仓观察等非交易指令式表述；
6. 风险：数据延迟、波动异常、信号矛盾、财报/停牌等可识别事件；
7. AI 解读：只引用结构化结果和数据状态，并允许用户继续追问。

## 4. 功能范围与分期

### Phase 0：修复基础与技术准备

- 修复现有 Agent/SSE 测试夹具的用户身份问题，恢复全绿测试基线。
- 增加 CI：后端测试、前端构建、数据库迁移校验、关键 API 冒烟测试。
- 将采集任务状态从进程内内存迁移为可持久化任务记录。
- 明确数据用途、延迟说明、免责声明、供应商许可与调用频率限制。

验收：主分支测试全绿；新环境可通过 Docker Compose 完成迁移、启动与健康检查。

### Phase 1：A 股个股与 ETF 一键分析 MVP

- 支持沪深 A 股和场内 ETF 的代码/名称搜索、自动市场识别和标的详情。
- 支持至少 250 个交易日日线 OHLCV 数据的拉取、缓存与增量更新。
- 实现 MA5/20/30/60、MACD、RSI(14)、布林带(20, 2σ)、ATR(14)、相对成交量。
- 实现结构化评分、趋势/波动/量价风险标签及报告保存。
- 新增 `/analysis` 页面，并将报告链接接入 AI 对话与历史记录。

验收：对任一支持标的，可从搜索到报告完成完整闭环；报告展示所有指标数值、计算日期和数据状态。

### Phase 2：可靠性、对比与移动端体验

- 建立数据源适配器、主备源和缓存降级机制。
- 记录每次请求的数据源、延迟、错误原因和数据新鲜度。
- 提供自选、批量刷新和 2–5 个标的比较。
- 完成 375px、768px、1280px 断点的界面验收；处理图表缩放和横屏。
- 增加刷新失败通知、任务重试与管理端数据健康页。

验收：主源故障时，系统明确切换或降级，不返回无时间标记的陈旧数据；移动端能完成搜索、阅读报告和查看图表。

### Phase 3：港股、美股、LOF 与高级能力

- 按同一 `Instrument`、`Quote`、`Candle` 领域模型接入港股、美股、LOF。
- 为各市场加入交易日历、币种、时区、复权和交易时段处理。
- 增加条件预警：均线突破、RSI 阈值、评分变化、成交量异常。
- 增加策略回测与历史信号评估；结果必须展示样本期、成本、滑点和局限。

验收：跨市场报告字段一致，报价币种/时区/复权方式可见；预警具有去重、静默期和退订机制。

## 5. 数据架构

### 5.1 领域模型

| 实体 | 关键字段 | 说明 |
| --- | --- | --- |
| `instruments` | `id, symbol, market, asset_type, name, exchange, currency, status` | 统一标的；市场和类型不再散落在 API 参数中 |
| `daily_candles` | `instrument_id, trade_date, open, high, low, close, volume, amount, adjusted_close, source` | 日线 OHLCV，唯一键为标的+日期+复权类型 |
| `latest_quotes` | `instrument_id, quote_time, price, change_pct, volume, source, delay_seconds` | 最新行情快照，显式标注延迟 |
| `data_source_runs` | `source, capability, started_at, ended_at, status, count, error` | 采集可观测性和故障定位 |
| `analysis_reports` | `user_id, instrument_id, period, input_data_at, scoring_version, result_json, created_at` | 不可变报告快照，支持复现与历史对比 |
| `watchlists` / `watchlist_items` | `user_id, name, instrument_id, sort_order` | 用户自选标的 |
| `alert_rules`（Phase 3） | `user_id, instrument_id, condition, threshold, channel, enabled` | 条件预警 |

原有基金、基金净值和建议表不替换；通过 `asset_type` 和独立报告类型建立关联，渐进迁移，避免破坏既有用户数据。

### 5.2 数据源策略

定义统一的 `MarketDataProvider` 接口：

```python
search_instruments(query, market) -> list[Instrument]
get_daily_candles(instrument, start, end, adjustment) -> list[Candle]
get_latest_quote(instrument) -> Quote
get_health() -> ProviderHealth
```

首期可使用 AKShare 作为 A 股/ETF 主源；生产环境还应配置至少一个有明确商用许可、SLA 与稳定接口的备用源。多源不是简单“失败时换接口”，还需要：

- 字段标准化：币种、单位、成交量、时区、复权格式统一；
- 数据校验：OHLC 合法性、日期连续性、价格跳变、重复和缺失；
- 优先级与熔断：连续失败时暂时隔离故障源，定时探测恢复；
- 缓存降级：返回最近可信快照，并突出显示“数据截至”；
- 审计：报告保存使用的数据源、原始时间和版本。

港美股数据源的选型需在接入前完成许可证、实时/延迟权限、成本、配额和数据再分发限制评估，不能仅以“接口可调用”作为上线依据。

## 6. 分析与评分引擎

### 6.1 计算原则

- 使用 pandas/TA 类库或自研纯函数计算，结果保存计算参数与版本号。
- 每个指标都返回“值、方向、阈值、证据、置信度”，而不是仅返回一个买卖结论。
- 数据不足时输出“不可判定”，不使用默认 50 分掩盖缺失。
- 评分规则先配置化、可解释，后续再引入回测校准；LLM 只负责语言表达与问答。

### 6.2 建议评分维度

| 维度 | 建议权重 | 主要输入 | 输出示例 |
| --- | ---: | --- | --- |
| 趋势 | 30% | MA5/20/30/60、均线斜率、价格位置 | 多头排列 / 趋势走弱 |
| 动量 | 25% | MACD、RSI、背离信号 | 动能增强 / 超买风险 |
| 波动与风险 | 20% | 布林带、ATR%、近期波动 | 波动可控 / 高波动 |
| 量价 | 15% | 相对成交量、价量变化 | 放量突破 / 缩量回调 |
| 市场环境 | 10% | 指数趋势、行业强弱、资金流 | 顺风 / 逆风 |

综合分限定在 0–100。建议映射可先定义为：`75–100 强势`、`60–74 偏强`、`40–59 观望`、`25–39 偏弱`、`0–24 弱势`。输出措辞应为分析倾向和风险管理提示，而非确定性投资承诺。

### 6.3 技术债务处理

现有 `TechnicalAnalyzer` 可保留接口，但应拆分为：`FundNavAnalyzer` 与 `OhlcvTechnicalAnalyzer`。前者只计算适用于基金净值的趋势/动量指标；后者才启用成交量、ATR、布林带和 K 线形态。这样可以避免把 `volume=0` 的基金净值当作股票 K 线来评分。

## 7. API 与前端接口

### 7.1 新增 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/instruments/search?q=&market=` | 搜索并识别标的 |
| `GET` | `/instruments/{id}` | 标的基础信息与可用数据范围 |
| `GET` | `/instruments/{id}/candles?period=1d&days=250` | K 线与成交量 |
| `GET` | `/instruments/{id}/quote` | 最新报价与延迟状态 |
| `POST` | `/analysis/reports` | 创建或读取分析报告 |
| `GET` | `/analysis/reports/{id}` | 获取完整结构化报告 |
| `GET` | `/analysis/reports?instrument_id=` | 获取报告历史 |
| `POST` | `/watchlists/items` | 收藏标的 |
| `DELETE` | `/watchlists/items/{id}` | 取消收藏 |
| `GET` | `/admin/data-sources/health` | 管理员查看数据源状态 |

创建报告接口应返回 `report_id`、`status` 和 SSE 订阅地址；数据抓取、计算或 AI 解读耗时较长时以前端进度事件呈现，不让请求静默超时。

### 7.2 与 AI Agent 的集成

新增工具：`search_instrument`、`get_instrument_quote`、`get_instrument_candles`、`create_analysis_report`、`get_analysis_report`、`compare_instruments`。工具响应保持结构化 JSON，Prompt 明确要求：

- 先引用报告时间和数据状态；
- 不编造价格、指标、财报或新闻；
- 当报告为陈旧/缺失时提示用户刷新；
- 不提供保证收益或直接交易指令。

## 8. 非功能要求

### 8.1 性能与可靠性

- 缓存未过期行情；同一标的同周期的短时间重复请求复用报告。
- 采集、指标计算、AI 解释拆为可重试后台任务；任务状态持久化。
- 为 API 设置超时、重试、限流和幂等键；避免页面重复点击产生并发抓取。
- 记录请求 ID、数据源、耗时、报告版本、异常原因和用户可见错误码。

### 8.2 安全与合规

- 延续服务端会话、HttpOnly Cookie、CSRF、用户数据隔离。
- 数据源密钥仅存服务端环境变量或密钥管理服务，不进入前端和 Git。
- 标注“数据可能延迟/缺失，本产品仅供信息辅助，不构成投资建议”。
- 对外展示的报价、历史数据和再分发方式需满足供应商许可与当地监管要求。

### 8.3 测试策略

| 层级 | 覆盖重点 |
| --- | --- |
| 单元测试 | 指标计算、评分边界、数据质量校验、复权与时区转换 |
| 适配器测试 | 每个数据源字段映射、超时、空数据、限流、主备切换 |
| API 测试 | 鉴权、用户隔离、报告创建/读取、任务状态与 SSE |
| 前端测试 | 搜索、错误提示、报告渲染、移动端断点 |
| 端到端测试 | 从输入 A 股代码到保存报告、AI 引用报告的完整路径 |
| 回归测试 | 固定历史样本的指标与评分快照，防止公式变更漂移 |

## 9. 实施顺序与里程碑

| 里程碑 | 关键产出 | 完成判定 |
| --- | --- | --- |
| M0 基线恢复 | 全绿测试、CI、任务持久化方案 | 现有能力可稳定回归 |
| M1 数据底座 | 统一标的、日线表、A 股/ETF Provider、数据校验 | 可可靠拉取并存储 250 日日线 |
| M2 分析内核 | OHLCV 指标、配置化评分、报告快照 | 同输入可复现同报告 |
| M3 产品闭环 | 搜索页、报告页、历史与 AI 引用 | 用户可独立完成一键分析 |
| M4 稳定性 | 主备源、缓存降级、可观测性、移动端验收 | 数据故障可见、可控、可恢复 |
| M5 多市场 | 港股/美股/LOF 适配器与交易日历 | 同一产品流程可跨市场使用 |

每个里程碑完成后均应发布可演示版本并收集真实用户反馈，再决定是否扩大市场覆盖，而不是一次性堆叠所有数据源和指标。

## 10. 风险与决策点

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 免费数据源限流、反爬、字段变动 | 行情缺失、报告错误 | Provider 抽象、缓存、备用源、健康监测 |
| 跨市场数据许可成本 | 无法合法商用或成本失控 | 接入前完成供应商与许可评审 |
| 技术指标被误解为投资建议 | 合规与用户风险 | 可解释证据、风险标签、显著免责声明 |
| 评分未经验证 | 用户过度信任 | 保持规则透明，增加回测与样本外评估 |
| LLM 幻觉 | 错误结论 | LLM 只解释结构化事实，回答必须带报告引用 |
| 范围膨胀 | 延迟 MVP 上线 | 固定 Phase 1 为 A 股个股 + ETF + 日线分析 |

## 11. Phase 1 的最终验收清单

- [ ] 用户可输入 A 股代码或名称，搜索结果能区分市场和标的类型。
- [ ] 用户可选择 A 股或 ETF，并生成一份日线分析报告。
- [ ] 报告含 OHLCV K 线、成交量、MA5/20/30/60、MACD、RSI、布林带、ATR。
- [ ] 报告含 0–100 总分、分项分、趋势、风险等级、证据和数据截至时间。
- [ ] 数据不足、源失败或报价延迟时，页面明确降级，不产生误导性结论。
- [ ] 同一用户只能读取自己的报告、自选和对话历史。
- [ ] 前后端构建、测试、迁移和容器健康检查均通过 CI。
- [ ] AI 回答可以引用报告，但不能脱离报告编造行情或给出保证收益式建议。

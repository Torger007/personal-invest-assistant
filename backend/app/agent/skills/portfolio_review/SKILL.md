# 持仓复盘 Skill

版本：1.0.2。触发条件：用户在“问 AI”中点击“帮我分析当前持仓”等推荐提问，或在对话中提出等价的持仓分析、复盘、变化比较问题。

## 取数与判断

1. 先读取带估值日期的当前持仓、市场概览、已有规则建议和基金比较。只使用服务端提供的当前用户身份与允许工具。
2. 数据不足时仅针对质量门指出的缺口补查，不重复抓取已经有效的数据；整次运行最多 10 次工具调用，质量门触发的补查最多 2 次。
3. 候选关注项按持仓影响、变化幅度、风险紧迫性、用户已确认的偏好及证据质量排序，最多保留三项。没有足够证据时不要补满三项。
4. 将持仓变化、数据变化、规则变化和判断延续分开描述。没有上一次成功复盘时标记首次复盘，不引用普通聊天摘要作历史判断。同日数据未变时不能把措辞差异当成新变化。
5. 每项实质性结论引用当前证据 ID；历史变化还要引用上次复盘保存的证据 ID 和两次时间。不得编造证据 ID。

## 降级与动作边界

- 净值、估值、市场或规则建议缺失、过期时，只说明可确认的事实、未知之处和下一步观察条件。交易日与净值公布窗口由服务端质量门裁定。
- 单基金操作、目标仓位和置信度只取有效规则决策产物；组合级具体调仓比例不得由模型计算。降级报告不得提出新增目标仓位。
- 输出必须符合 `PortfolioReviewResult`，包括状态、各数据时间、最多三项关注项、与上次相比、限制和证据 ID。模型提出的字段须通过服务端契约与证据校验后才能展示。
